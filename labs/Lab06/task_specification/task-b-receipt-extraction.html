Task guidelines

Reference while you work

Extract the total amount payable from receipts to support automated expense processing.

Your role
Receipt annotator
Unit
One complete receipt
How to annotate
  1. Inspect the receipt image.
  2. Read the monetary amounts and their associated field names.
  3. Find the total amount payable.
  4. Enter the amount in the annotation field.
  5. Use the receipt’s original currency.
  6. If the value is not present, select Not found.

You may correct the suggested value. Use the receipt to verify the OCR suggestion.

Field definition
Total amount payable

The monetary amount representing the total payment associated with the receipt.

Common labels include TOTAL, AMOUNT DUE, TOTAL AMOUNT and BALANCE DUE.

Exclusions

Do not select subtotal before additional charges, tax amount alone, service charges alone, or individual item prices.

Formatting rules
  • Enter the monetary value as a number.
  • Use a period as the decimal separator.
  • Do not include the currency symbol.

Example: enter 14.50 rather than €14,50.

Training examples
Example 1 · Standard receipt

Coffee: €4.50
Sandwich: €8.00
Subtotal: €12.50
Tax: €2.50
TOTAL: €15.00

Expected annotation: 15.00. The total includes the subtotal and additional charges.

Example 2 · Multiple monetary fields

Subtotal: €20.00
Tax: €3.80
TOTAL: €23.80

Expected annotation: 23.80. The subtotal and tax are components of the final total, not the requested field. Counterexample: 20.00 is the subtotal, not the requested field.

Exceptional cases

Not found: Use when no relevant total amount can be identified on the receipt.

Unclear OCR: Refer to the receipt image when OCR text is incomplete or incorrect.

If necessary, add a note explaining a difficult judgment.

Strength

Strength

Structured numeric output

A numeric response and formatting guidance support consistent machine-readable extraction. View related element ↗

Lecture concept: Response schema and annotation guidelines

Possible improvement: Keep the numeric format and document how to handle currency conventions.

Weakness

The field definition conflates labels

TOTAL and BALANCE DUE can describe different monetary concepts; the definition does not resolve which one is intended. View related element ↗

Lecture concept: Operational definitions

Possible improvement: Separate transaction total from outstanding balance and define each field.

Potential bias

The suggestion is pre-filled

A pre-filled value may anchor annotators toward accepting the OCR suggestion; its effect needs testing. View related element ↗

Lecture concept: Task-design bias and anchoring

Possible improvement: Compare pre-filled suggestions with suggestions shown only after an independent judgment.

Partial strength

Not found covers absence

The option handles absent values but does not express conflicting or insufficiently distinguishable candidates. View related element ↗

Lecture concept: Exception handling

Possible improvement: Add a structured ambiguity or escalation response with clear instructions.

Boundary case

Total and remaining balance coexist

This receipt contains a transaction total and an outstanding balance, requiring a clearer field rule. View related element ↗

Lecture concept: Boundary cases and context

Possible improvement: Specify which monetary concept to extract and provide examples with partial payments.
